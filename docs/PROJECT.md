# 项目说明

## 定位与目标

Agent Nexus：通过任何移动设备的浏览器，查看和接管电脑上的 AI 编程会话，保留现有工作环境。

## 起因

AN 起于一个很具体的问题：楚齐同学在电脑上使用 AI 编程工具，但人不可能一直坐在电脑前。想从另一台设备查看或接管本机会话时，Codex 的远程入口主要依赖账号体系，不能直接当作自建 API 使用；WorkBuddy、DeepSeek Harness 等类似工具也普遍把远程能力和各自登录账号、云端服务绑定在一起。

因此 AN 的方向不是再造一个云端账号平台，而是让电脑保留项目、文件、工具和本机 Agent，移动设备只作为浏览器控制面板。长期目标是尽可能摆脱不必要的账号和平台限制，让用户可以拥有自己的连接方式、自己的档案和自己的运行环境。

楚齐同学认为，共产主义社会不应该存在这些不必要的限制。这个判断是项目的价值取向，不是对当前技术完成度的夸张承诺。现阶段外部 Agent 的登录、模型权限和服务条款仍然存在；AN 先做到不新增一套 AN 云账号，尽量复用用户自己电脑上已有的本地环境，并把限制公开记录下来。

目标用户已经在电脑上使用编码 Agent，但需要离开桌面后查看任务、补充指令、处理审批或停止执行。AN 将浏览器入口、项目/会话视图、运行状态和远程控制连接起来。

## 工作链路

1. 用户在电脑安装、配置并登录原有 Agent。
2. AN 网关读取本机索引、项目/会话信息，并连接本机执行适配器。
3. 用户通过移动浏览器的私人链接认证，选择已有项目或会话。
4. 指令持有稳定请求标识；网关记录提交意图并调用目标引擎。
5. 引擎继续在本机执行，AN 将流式事件和状态送到浏览器。
6. 网络断开后，浏览器按序号恢复，并通过会话投影对账；无法确认的执行结果保留待确认状态。

## 设计重点

- 保留本机工作目录、文件、工具链和原有账号，移动端无须再部署一套开发环境。
- REST 负责状态与操作，WebSocket 传递事件；模型调用由既有 Agent 执行。
- 稳定身份与持久化收据降低重复网络提交引发的重复执行。
- 命令、任务意图和事件的事务边界可在一次性 workflow 层核查与测试。
- 同时支持多个引擎，但明确展示各自语义和兼容性边界。

## 已实现与后续

已实现：远程会话、流式事件、原生 Codex 项目映射、内部线程过滤、设置回读、队列恢复、一次性 workflow、桌面/移动响应式 UI。

后续优先项：CC/WorkBuddy 草稿和桌面原生创建行为一致性、跨版本协议测试、真实断网压力与多端并发回归、稳定域名部署、更多无障碍和移动浏览器验收。

本项目不声称零 token 成本。状态查询本身不应调用模型；用户消息、工作流实际执行及引擎自身重试仍可能消耗模型额度。持久幂等不等于所有外部工具均能严格 exactly-once。
